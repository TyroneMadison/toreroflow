# M6: Package and polish, design

Date: 2026-07-25
Status: approved
Spec reference: `07-24-2026-toreroflow-build-spec.md` Section 12, M6

## Goal

Close the final build-spec milestone: the app updates itself, surfaces
failures instead of swallowing them, and looks correct in both themes with
real loading and empty states on every screen.

## Scope

In:

1. Auto-update via GitHub Releases
2. Error toasts
3. Light and dark theme parity
4. Empty and loading states

Out, by decision on 2026-07-25:

- **Code signing.** Skipped entirely. Installers stay unsigned; Windows
  SmartScreen is a one-time click on Tyrone's own machines. Not scheduled,
  not committed to any vendor. See "Signing, when wanted" below for the
  path if he ever chooses to.
- **Mac installers.** Both machines are Windows.
- **Shareable read-only report link.** A real feature, not polish. Deferred.
- **Accounts card "total followers" stat.** Still shows "-"; deferred to
  the bug-fixing pass.

## 1. Auto-update

Tauri's `updater` plugin, serving from GitHub Releases on the existing
public repo.

- **Check on launch**, non-blocking and silent when there is nothing new,
  so a cold start never waits on the network.
- **Manual "Check for updates"** button in Settings, next to the current
  version number, so an update can be pulled on demand.
- **Update signing keypair**: minisign, generated by the Tauri CLI. This is
  the updater's own integrity check and is unrelated to code signing. The
  public key lives in `tauri.conf.json`; the private key and its password
  live in the gitignored root `.env` and never enter git.
- **Release flow**: a script builds the bundles, then publishes the tag,
  the installers, and `latest.json` to GitHub Releases.

Rejected alternatives: silent auto-install on launch (surrenders control of
when the app restarts) and manual-check-only (defeats the laptop case that
motivated the feature).

### Versioning

Every version file still reads `0.1.0` and only `v0.1.0` was ever tagged,
though the build is through M5. The changelog convention maps minor
versions to milestones (0.1 = M0 … 0.7 = M6), so **M6 ships as v0.7.0**,
bumped in `tauri.conf.json`, `apps/desktop/package.json`, and the root
`package.json` together.

This produces the milestone's acceptance test for free: the copy currently
installed at `%LOCALAPPDATA%\Toreroflow` reports 0.1.0, so once 0.7.0 is on
GitHub Releases it must detect and install the update on its own.

## 2. Error toasts

Today roughly 39 catch sites mostly swallow errors, several as bare
`catch {}`. When the API is down, buttons appear to do nothing.

**Hybrid approach:**

- A toast context and provider holding a small queue of messages.
- Wired into `apps/desktop/src/lib/api.ts` so every failed request raises a
  toast automatically, including the currently-silent ones.
- An opt-out flag for deliberately quiet calls: the `ApiStatus` heartbeat
  poll and optional analytics fetches, which fail normally and already have
  their own UI.
- Explicit toast calls for failures that are not HTTP, such as upload
  validation and file errors.

Rejected alternatives: editing all 39 catch sites by hand (most control,
but guarantees missed sites) and toasting only at call sites already being
touched (leaves the silent failures silent).

Behavior: stack bottom-right, auto-dismiss around 6 seconds, dismissable on
click, red for errors and green for confirmations, glass styling and theme
tokens consistent with the rest of the app.

## 3. Theme parity and states

A systematic pass rather than an architectural change.

- Visit every screen in both themes at a wide and a narrow window width.
- Fix contrast failures and any hardcoded colors that do not resolve in
  light mode. The newest analytics CSS is the most likely offender, since
  it was authored and QA'd primarily in dark.
- Confirm each screen has a real loading state and a real empty state
  rather than a blank card, and that empty states say what to do next.

## Acceptance

1. The installed 0.1.0 app detects 0.7.0 on GitHub Releases and updates
   itself; Settings shows the version and its manual check works.
2. Stopping the API and clicking through the app produces visible error
   toasts instead of dead buttons.
3. Every screen reads correctly in both themes and shows sensible loading
   and empty states.
4. Workspace typecheck passes; CHANGELOG updated; tagged v0.7.0.

## Signing, when wanted

Not scheduled. If it is ever wanted, the cheapest current path is Azure
Trusted Signing (roughly $10/month, requires an Azure account and business
identity verification). Traditional OV/EV certificates run $200-600/year,
and only EV clears SmartScreen immediately. Wiring it up means adding a
signing step to the bundle build; nothing else in this design changes.
